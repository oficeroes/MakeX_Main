# 遥控算法详解 — 从摇杆到轮子的完整信号链

> **适用场景**：任何使用手柄遥控的轮式机器人底盘（麦克纳姆、全向、差速等）。  
> **来源**：`mecanum_drive.py` — 四轮麦克纳姆底盘遥控程序，经多轮调优沉淀而成。  
> **可复用性**：除运动学部分与底盘构型绑定外，其余 5 个阶段对任意底盘通用。

---

## 一、总览：7 阶段信号链

```
┌──────────┐   ┌──────────┐   ┌──────────┐   ┌──────────┐   ┌──────────┐   ┌──────────┐   ┌──────────┐
│  ① 死区   │→ │ ② 响应   │→ │ ③ 速度   │→ │③½ 精细   │→ │ ④ 方向   │→ │ ⑤ 运动学  │→ │ ⑥ 电机   │
│  过滤     │   │  曲线    │   │  缩放    │   │  操控    │   │  校准    │   │  解算    │   │  后处理  │
└──────────┘   └──────────┘   └──────────┘   └──────────┘   └──────────┘   └──────────┘   └──────────┘
 摇杆原始值      手柄手感      全局速度      自动检测       正反/面翻转    底盘构型       静摩擦+托底
 (±100)         控制         倍率         反复微调                       (Vx,Vy,ω)
               (用原始值                     → 降速                       → 各轮功率%
                做检测)
```

### 调用链（正常模式主循环）

```python
# 读取摇杆 → 保存原始值（用于阶段③½精细操控检测）
Lx = gamepad.get_joystick("Lx")
Ly = gamepad.get_joystick("Ly")
Rx = gamepad.get_joystick("Rx")
_raw_Lx, _raw_Ly, _raw_Rx = Lx, Ly, Rx   # 原始值：反映操作者真实物理输入

# ① 死区过滤
Lx = apply_dead_zone(Lx)        # |值| < DEAD_ZONE → 0

# ② 响应曲线
Lx = apply_response_curve(Lx, JOYSTICK_EXPO)   # 指数曲线 + 抬升
Ly = apply_response_curve(Ly, JOYSTICK_EXPO)
Rx = apply_response_curve(Rx, OMEGA_EXPO)      # 旋转可用独立曲线

# ③ 速度缩放
Vx = Lx * SPEED_SCALE
Vy = Ly * SPEED_SCALE
omega = Rx * SPEED_SCALE

# ③½ 精细操控检测（基于原始值，在方向校准之前）
_fine_scale = fine_control_tick(_raw_Lx, _raw_Ly, _raw_Rx, novapi.timer())
Vx *= _fine_scale
Vy *= _fine_scale
omega *= _fine_scale

# ④ 方向校准 + 面翻转
if INVERT_VX: Vx = -Vx
if INVERT_VY: Vy = -Vy
if INVERT_OMEGA: omega = -omega
if face_flipped: Vx, Vy = -Vx, -Vy

# ⑤ 运动学解算
M1, M2, M3, M4 = mecanum_kinematics(Vx, Vy, omega)

# ⑥ 电机后处理
M1, M2, M3, M4 = startup_burst(M1, M2, M3, M4, novapi.timer())

# 输出
motor_M1.set_power(M1)  # ... 等
```

## 二、逐阶段详解

### 阶段①：死区过滤 `apply_dead_zone()`

**目的**：消除摇杆中位抖动，避免不碰手柄时小车自己漂移。

```python
DEAD_ZONE = 0   # 死区阈值：|value| < DEAD_ZONE → 强制归零

def apply_dead_zone(value, threshold=DEAD_ZONE):
    if abs(value) < threshold:
        return 0
    return value
```

**设计要点**：

- 设为 `0` 表示不做死区（配合响应曲线的抬升机制，低段已有良好手感）
- 传统做法设 5~10，但会损失低速控制精度
- 如果摇杆硬件本身无漂移，推荐 `0` + 用曲线抬升替代

---

### 阶段②：响应曲线 `apply_response_curve()`

**这是整套算法最核心的设计。** 解决两个矛盾：

1. **低速要跟手**：轻推摇杆车就要动（不能有"死行程"）
2. **高速要细腻**：推满前的最后一小段也要可精确控制

#### 数学公式

$$output = \text{sign}(v) \times \left[ L + (100 - L) \times \left( \frac{|v|}{100} \right)^E \right]$$

| 符号 | 含义              | 对应参数                       |
| ---- | ----------------- | ------------------------------ |
| $v$  | 摇杆原始值 (±100) | —                              |
| $E$  | 指数 (exponent)   | `JOYSTICK_EXPO` / `OMEGA_EXPO` |
| $L$  | 曲线抬升量 (%)    | `CURVE_LIFT`                   |

#### 纯指数 vs 抬升曲线（E=2.0）

| 摇杆 % | 纯指数输出 | 抬升后 (L=15) | 抬升后 (L=20) |
| ------ | ---------- | ------------- | ------------- |
| 0%     | 0%         | 0%            | 0%            |
| 5%     | 0.25%      | **15.2%**     | **20.2%**     |
| 10%    | 1.0%       | **15.9%**     | **20.8%**     |
| 20%    | 4.0%       | 18.4%         | 23.2%         |
| 50%    | 25.0%      | 36.3%         | 40.0%         |
| 100%   | 100%       | 100%          | 100%          |

> **关键效果**：摇杆刚离开零点就有 `L%` 输出，彻底消灭"轻推不动"的死区感。

#### 代码

```python
CURVE_LIFT = 20          # 曲线最低输出% (0=关闭)
JOYSTICK_EXPO = 2.0      # 平移指数 (越大低速越细腻，越小越线性)
OMEGA_EXPO = 2.0         # 旋转指数 (可与平移不同)

def apply_response_curve(value, exponent=JOYSTICK_EXPO, max_input=100.0):
    if value == 0:
        return 0.0
    sign = 1.0 if value > 0 else -1.0
    normalized = abs(value) / max_input
    curved = normalized ** exponent

    if CURVE_LIFT > 0:
        lift = CURVE_LIFT / max_input
        curved = lift + (1.0 - lift) * curved

    return sign * curved * max_input
```

**设计要点**：

- `CURVE_LIFT` 和 `JOYSTICK_EXPO` 是两个正交维度：一个控"起步力度"，一个控"中高速手感"
- 旋转可用 `OMEGA_EXPO` 独立设置，因为旋转惯性不同于平移
- 如果底盘非常轻（如小型差速车），`CURVE_LIFT` 可降至 5~10

---

### 阶段③：速度缩放 `SPEED_SCALE`

**目的**：限制全局最大功率，保护机械 + 防止新手全速撞墙。

```python
SPEED_SCALE = 0.85   # 摇杆推满 = 85% 最大功率

Vx = Lx * SPEED_SCALE
Vy = Ly * SPEED_SCALE
omega = Rx * SPEED_SCALE
```

**设计要点**：

- 曲线输出 100% → 实际功率 85%，留 15% 余量应对补偿叠加（前后补偿、起步助推等）
- 比赛时可调到 1.0 发挥全部功率
- 这个阶段之后 Vx/Vy/omega 才进入运动学

---

### 阶段③½：精细操控模式 `fine_control_tick()`

**这是 2026-07-08 新增的阶段。** 解决操作手反复反馈的问题：

> "摇杆在做精细操作（推动幅度非常小）的时候，小车要么不动，要么就动一大段，很难做到慢慢动。"

#### 问题根源

阶段②的响应曲线有 `CURVE_LIFT`（默认 16~20%），摇杆一推就跳到 16~20% 功率。这解决了"轻推不动"的问题，但也带来了副作用：**操作者无法输出 1%~15% 的极低功率**，精细对准变得困难。

操作者会本能地反复轻推摇杆来"试探"——这正是我们需要检测的信号。

#### 算法原理

```
                     ┌─────────────────────────────────┐
                     │       fine_control_tick()        │
                     │                                 │
  原始摇杆值 ──────→ │  ① 计算 max_raw = max(|Lx|,|Ly|,|Rx|)  │
  (曲线/死区前)      │                                 │
                     │  ② 未在精细模式:                   │
                     │     max_raw < 22% 持续 500ms      │
                     │     + 检测到 ≥3 次"微调"           │
                     │     → 进入精细模式, 速度 ×0.30      │
                     │                                 │
                     │  ③ 已在精细模式:                   │
                     │     max_raw > 55% 连续 6 帧        │
                     │     → 退出精细模式, 恢复正常        │
                     │                                 │
                     └─────────────┬───────────────────┘
                                   │
                                   ▼
                          返回 1.0 或 0.30
                          (乘到 Vx, Vy, omega 上)
```

#### 三个关键设计决策

**决策 1：用原始摇杆值做检测，而非处理后的值**

| 方案         | 问题                                    |
| ------------ | --------------------------------------- |
| 用处理后值   | 曲线抬升后 5% → 20%，永远检测不到"低值" |
| **用原始值** | 真实反映操作者的物理输入，5% 就是 5%    |

**决策 2：必须检测"反复微调"，而非仅仅"低值"**

如果操作者只是把摇杆稳定在 10% 前进，那是**有意低速巡航**，不应触发降速。
只有当操作者在低值范围内**反复改变摇杆方向/幅度**（如 ±5% 来回推），才说明在做精细对准。

检测方式：统计主导轴（绝对值最大的轴）的值变化次数。每次变化 >3% 计为一次"微调"。

**决策 3：带迟滞的退出机制**

| 状态     | 阈值      | 说明                         |
| -------- | --------- | ---------------------------- |
| 进入     | < 22%     | 低阈值，只有真正微调才触发   |
| 退出     | > 55%     | 高阈值，需要明确"推大"才退出 |
| 退出延迟 | 连续 6 帧 | 防止偶尔尖峰误退出           |

进入和退出之间 22%→55% 的差距（33 个百分点）形成**迟滞带**，防止在阈值边界上来回抖动。

#### 参数配置

```python
FINE_CONTROL_ENABLE = True        # 总开关 (False=关闭整个功能)
FINE_CONTROL_ENTER_THRESHOLD = 22 # 进入阈值：原始摇杆值% (所有轴低于此值持续 → 候选)
FINE_CONTROL_EXIT_THRESHOLD = 55  # 退出阈值：原始摇杆值% (任一轴超过此值 → 退出)
FINE_CONTROL_SPEED_SCALE = 0.30   # 精细模式下的速度倍率 (0.30 = 降至正常 30%)
FINE_CONTROL_WINDOW_MS = 500      # 时间窗口：摇杆需持续低值这么久才进入 (毫秒)
FINE_CONTROL_EXIT_FRAMES = 6      # 迟滞帧数：连续超过退出阈值这么多帧才退出
FINE_CONTROL_ACTIVITY_MIN = 3     # 最少微调次数：窗口内需检测到这么多次调整才触发
```

#### 调参指南

| 现象                         | 调整                                  |
| ---------------------------- | ------------------------------------- |
| 精细模式太难触发（要摇很久） | ↓ `FINE_CONTROL_WINDOW_MS` 到 300ms   |
| 精细模式太容易触发（误触）   | ↑ `FINE_CONTROL_WINDOW_MS` 到 800ms   |
| 精细模式下还是太快           | ↓ `FINE_CONTROL_SPEED_SCALE` 到 0.20  |
| 精细模式下太慢、无力         | ↑ `FINE_CONTROL_SPEED_SCALE` 到 0.40  |
| 稍微推大一点就退出           | ↑ `FINE_CONTROL_EXIT_THRESHOLD` 到 65 |
| 退出太慢、需要推很深才恢复   | ↓ `FINE_CONTROL_EXIT_THRESHOLD` 到 45 |
| 静止不动也触发精细模式       | ↑ `FINE_CONTROL_ACTIVITY_MIN` 到 5    |
| 已经在微调但不触发           | ↓ `FINE_CONTROL_ACTIVITY_MIN` 到 2    |

#### 完整代码

```python
def fine_control_tick(raw_Lx, raw_Ly, raw_Rx, now):
    """精细操控模式检测：操作者持续低摇杆值 + 反复微调 → 自动降速。

    检测逻辑 (全部基于原始摇杆值, 在死区/曲线之前):
      1. max_raw = 三轴绝对值最大值
      2. 未在精细模式:
         - max_raw < ENTER_THRESHOLD → 开始计时 + 统计微调次数
         - 持续 WINDOW_MS 且微调次数 ≥ ACTIVITY_MIN → 进入精细模式
         - max_raw 一旦超过阈值 → 重置计时
      3. 已在精细模式:
         - max_raw > EXIT_THRESHOLD → 累加退出帧计数
         - 连续 EXIT_FRAMES 帧 → 退出精细模式
         - 否则衰减计数 (防止偶尔尖峰误退出)
      4. 返回: 1.0 (正常) 或 FINE_CONTROL_SPEED_SCALE (精细)

    "微调"定义: 主导轴的值相比上一帧变化超过 3%。
    这样只有操作者在反复推摇杆时才触发，单纯低速巡航不会误触。
    """
    global _fine_mode, _fine_low_since, _fine_high_count
    global _fine_activity_count, _fine_last_dominant

    if not FINE_CONTROL_ENABLE:
        return 1.0

    max_raw = max(abs(raw_Lx), abs(raw_Ly), abs(raw_Rx))

    # 确定主导轴 (绝对值最大的轴, 用于微调检测)
    if abs(raw_Ly) >= abs(raw_Lx) and abs(raw_Ly) >= abs(raw_Rx):
        dominant = raw_Ly
    elif abs(raw_Lx) >= abs(raw_Rx):
        dominant = raw_Lx
    else:
        dominant = raw_Rx

    if not _fine_mode:
        # ---- 未在精细模式: 检测进入条件 ----
        if max_raw < FINE_CONTROL_ENTER_THRESHOLD:
            if _fine_low_since == 0.0:
                _fine_low_since = now
                _fine_activity_count = 0
                _fine_last_dominant = dominant

            # 微调检测: 主导轴值变化 > 3% (排除传感器噪声)
            if abs(dominant - _fine_last_dominant) > 3.0:
                _fine_activity_count += 1
            _fine_last_dominant = dominant

            # 持续时间达标 + 有足够的微调次数 → 进入精细模式
            window_s = FINE_CONTROL_WINDOW_MS / 1000.0
            if (now - _fine_low_since) >= window_s:
                if _fine_activity_count >= FINE_CONTROL_ACTIVITY_MIN:
                    _fine_mode = True
                    _fine_high_count = 0
        else:
            # 摇杆推大了 → 重置计时
            _fine_low_since = 0.0
            _fine_activity_count = 0
    else:
        # ---- 已在精细模式: 检测退出条件 ----
        if max_raw > FINE_CONTROL_EXIT_THRESHOLD:
            _fine_high_count += 1
            if _fine_high_count >= FINE_CONTROL_EXIT_FRAMES:
                _fine_mode = False
                _fine_low_since = 0.0
                _fine_activity_count = 0
                _fine_high_count = 0
        else:
            # 衰减计数 (避免偶尔尖峰误退出, 提供迟滞)
            _fine_high_count = max(0, _fine_high_count - 1)

    return FINE_CONTROL_SPEED_SCALE if _fine_mode else 1.0
```

#### 状态变量

```python
_fine_mode = False               # 当前是否处于精细操控模式
_fine_low_since = 0.0            # 摇杆持续低值的起始时刻 (秒)
_fine_high_count = 0             # 连续超过退出阈值的帧计数
_fine_activity_count = 0         # 低值窗口内检测到的"微调"次数
_fine_last_dominant = 0.0        # 上一帧主导轴的值 (用于检测微调变化)
```

#### LED 反馈

根据项目核心铁律（"关键状态必须同步显示在 LED 屏上"），精细模式激活时 LED 显示前缀从 `S` 变为 `f`：

- 正常模式：`S80`（S = Speed，80 = 无刷电机速度）
- 精细模式：`f80`（f = fine，提醒操作者当前处于精细操控）

#### 为什么放在阶段③和④之间？

| 插入位置         | 评估                                                    |
| ---------------- | ------------------------------------------------------- |
| 曲线之前         | 会影响曲线形状，精细模式下的低速手感变差                |
| 曲线之后、缩放后 | ✅ **最佳**：保留曲线的手感形状，单纯做整体降速         |
| 运动学之后       | 逐轮缩放可能破坏运动学平衡，且与 min_power 等后处理冲突 |

#### 与现有补偿的关系

- **不影响** 方向校准（`INVERT_*`）、面翻转（`face_flipped`）：乘法和取反可交换
- **不影响** 重量补偿、旋转均衡：这些内嵌在运动学函数中，在精细缩放之后
- **不与** 起步助推冲突：精细模式降低了稳态功率，但助推在功率跳变时仍正常触发
- **不影响** 自动程序和调试模式：精细检测仅在正常遥控模式下运行

### 阶段④：方向校准 + 面翻转

```python
INVERT_VX = False     # 左右方向取反
INVERT_VY = True      # 前后方向取反
INVERT_OMEGA = True   # 旋转方向取反

face_flipped = False  # L1 键切换：机器人正面↔反面
```

**设计要点**：

- `INVERT_*` 在代码里写死，适配接线方向 → 摇杆前推车往前走
- `face_flipped` 是运行时切换：比赛机器人可能正面朝向对手，也可能反过来
- 面翻转只影响 Vx/Vy，不影响 omega（旋转方向是绝对的）

### 阶段⑤：运动学解算 `mecanum_kinematics()`

**这是唯一与底盘构型绑定的阶段。** 换底盘只需替换此函数。

#### X 型麦克纳姆轮运动学

```
         M1 (前左)    M2 (前右)
              \        /
               \      /
                [车身]
               /      \
              /        \
         M3 (后左)    M4 (后右)
```

**正向运动学**（Vx/Vy/ω → 各轮速度）：

$$M_1 = V_x + V_y + \omega$$
$$M_2 = -V_x + V_y - \omega$$
$$M_3 = -V_x + V_y + \omega$$
$$M_4 = V_x + V_y - \omega$$

M2、M4 接线反向 → 输出取反。

#### 重量补偿（三件套，内嵌在运动学函数中）

| 补偿项   | 参数                      | 作用                       | 何时需要             |
| -------- | ------------------------- | -------------------------- | -------------------- |
| 前后补偿 | `FRONT_BACK_COMPENSATION` | 前轮 ×(1+fb)，后轮 ×(1-fb) | 尾重/头重不均        |
| 旋转均衡 | `ROTATION_BALANCE`        | 旋转时前轮额外加力         | 尾重导致旋转时甩尾   |
| 平移耦合 | `STRAFE_VY_COUPLING`      | 平移时自动减 Vy 防漂移     | 尾重导致平移时向前漂 |

```python
FRONT_BACK_COMPENSATION = 0.07   # 尾重头轻 → 前轮加 7%，后轮减 7%
ROTATION_BALANCE = 0.0           # 旋转均衡 (当前关闭)
STRAFE_VY_COUPLING = 0.05        # 平移耦合补偿
```

#### 运动学函数完整代码

```python
def mecanum_kinematics(Vx, Vy, omega):
    # ① 平移耦合补偿
    sc = STRAFE_VY_COUPLING
    if sc > 0.001 and abs(Vx) > abs(Vy) and abs(Vx) > 0.5:
        Vy = Vy - abs(Vx) * sc

    # ② 标准逆运动学
    M1 =  Vx + Vy + omega
    M2 = -Vx + Vy - omega
    M3 = -Vx + Vy + omega
    M4 =  Vx + Vy - omega

    # ③ 接线反向修正
    M2 = -M2
    M4 = -M4

    # ④ 前后重量补偿
    fb = FRONT_BACK_COMPENSATION
    if fb > 0.001:
        M1 *= 1.0 + fb;  M2 *= 1.0 + fb   # 前轮加力
        M3 *= 1.0 - fb;  M4 *= 1.0 - fb   # 后轮减力

    # ⑤ 旋转均衡补偿
    rb = ROTATION_BALANCE
    if rb > 0.001:
        M1 *= 1.0 + rb;  M2 *= 1.0 + rb
        M3 *= 1.0 - rb;  M4 *= 1.0 - rb

    # ⑥ 功率钳位 (任一轮 >100 则等比缩放)
    max_abs = max(abs(M1), abs(M2), abs(M3), abs(M4))
    if max_abs > 100:
        scale = 100.0 / max_abs
        M1 *= scale; M2 *= scale; M3 *= scale; M4 *= scale

    # ⑦ 最小功率托底
    M1 = apply_min_power(M1)
    M2 = apply_min_power(M2)
    M3 = apply_min_power(M3)
    M4 = apply_min_power(M4)

    return M1, M2, M3, M4
```

**功率钳位说明**：如果某一轮算出来是 120%，四轮一起等比缩放到 100%。这保证了运动方向不变，只是整体减速。

### 阶段⑥：电机后处理

运动学输出已经可以直接驱动电机，但还有两重保护：

#### 6a. 最小功率托底 `apply_min_power()`

```python
MIN_MOTOR_POWER = 10   # 电机安全兜底

def apply_min_power(power):
    if MIN_MOTOR_POWER <= 0:
        return power
    if 0 < power < MIN_MOTOR_POWER:
        return MIN_MOTOR_POWER
    if -MIN_MOTOR_POWER < power < 0:
        return -MIN_MOTOR_POWER
    return power
```

**规则**：$0 < |power| < MIN \rightarrow |power| = MIN$；$power = 0$ 保持不变。

> ⚠️ `MIN_MOTOR_POWER` 应 < `CURVE_LIFT × SPEED_SCALE`，否则曲线抬升无效（全被硬夹覆盖）。

#### 6b. 起步助推 `startup_burst()`

**解决"刚启动时个别轮子卡住"的问题**，不读取任何传感器，零延迟。

```python
STARTUP_BURST_ENABLE = True   # 总开关
STARTUP_BURST_PCT = 30        # 起步额外加力%
STARTUP_BURST_MS = 150        # 助推持续毫秒

def startup_burst(m1_pwr, m2_pwr, m3_pwr, m4_pwr, now):
    global _burst_until, _last_nonzero

    if not STARTUP_BURST_ENABLE:
        return m1_pwr, m2_pwr, m3_pwr, m4_pwr

    powers = [m1_pwr, m2_pwr, m3_pwr, m4_pwr]
    adjusted = list(powers)
    burst_end = now + STARTUP_BURST_MS / 1000.0

    for i in range(4):
        is_running = abs(powers[i]) > 0
        if is_running and not _last_nonzero[i]:
            _burst_until[i] = burst_end     # 0→非0：开始助推
        _last_nonzero[i] = is_running

        if now < _burst_until[i] and abs(powers[i]) > 0:
            sign = 1 if powers[i] >= 0 else -1
            boosted = abs(powers[i]) + STARTUP_BURST_PCT
            adjusted[i] = sign * min(100, boosted)

    return tuple(adjusted)
```

**为什么不用速度传感器**：`get_value("speed")` 每次调用可能耗时 1~5ms（I²C 通信），4 个电机就是 4~20ms。在主循环 20ms 的前提下，这会让操控有明显延迟。起步助推基于"功率跳变检测"而非"速度反馈"，完全零延迟。

**状态变量**（需在模块级初始化）：

```python
_burst_until = [0.0, 0.0, 0.0, 0.0]        # M1~M4 助推结束时刻
_last_nonzero = [False, False, False, False] # 上一轮各电机是否在转
```

## 四、适配其他底盘

### 4.1 只换运动学函数

换底盘时，**阶段①②③④⑥全部不变**，只需替换阶段⑤的运动学函数。

#### 三轮全向 (Kiwi Drive)

```python
# 三轮 120° 均布全向轮
import math
R = math.radians(30)   # 轮子安装角

def omni3_kinematics(Vx, Vy, omega):
    M1 = -Vy * math.cos(R) - Vx * math.sin(R) + omega
    M2 =  Vy * math.cos(R) - Vx * math.sin(R) + omega
    M3 =  Vx + omega
    return M1, M2, M3
```

#### 双轮差速

```python
def diffdrive_kinematics(Vx, Vy, omega):
    # Vy=前后, Vx 忽略
    left  = Vy + omega
    right = Vy - omega
    return left, right
```

### 4.2 调整补偿层

- **三轮全向**：通常不需要 `FRONT_BACK_COMPENSATION`（三点支撑自然均衡），但 `STRAFE_VY_COUPLING` 可能仍需
- **差速底盘**：不需要平移耦合补偿（不能横移），但前后补偿和旋转均衡同样适用
- **履带底盘**：`MIN_MOTOR_POWER` 应调高（履带静摩擦大），`STARTUP_BURST_PCT` 也应调高

### 4.3 电机后处理通用性

`apply_min_power()` 和 `startup_burst()` 与底盘构型**完全无关**——它们只关心"电机功率是否太低"，适用于任何电机驱动的底盘。

## 五、调试流程（推荐顺序）

```
① 先关所有补偿，只跑基础运动学
   → 确认 Vx/Vy/ω 方向正确 (INVERT_*)

② 调 CURVE_LIFT，让轻推有反应
   → 从 10 开始，每次 +5 到满意

③ 调 JOYSTICK_EXPO，控制中高速手感
   → 2.0=标准，1.3=激进，1.0=线性

④ 调前后补偿，纠正直走偏斜
   → FRONT_BACK_COMPENSATION 从 0.03 开始 +0.02

⑤ 开启 MIN_MOTOR_POWER → 起步助推
   → MIN=10, BURST_PCT=20, BURST_MS=150 起步

⑥ 调精细操控模式
   → 反复轻推摇杆 0.5 秒，确认 LED 从 S→f（进入精细模式）
   → 推大摇杆，确认 LED 从 f→S（退出精细模式）
   → 不适配则调 FINE_CONTROL_SPEED_SCALE（太猛↓，太弱↑）

⑦ 路跑微调
   → 每次只改一个参数，跑一圈感受
```

## 六、常见问题

| 现象                   | 原因                                                 | 解决                                          |
| ---------------------- | ---------------------------------------------------- | --------------------------------------------- |
| 轻推不动               | `CURVE_LIFT` 太小                                    | +5                                            |
| 轻推窜车               | `CURVE_LIFT` 太大或 `STARTUP_BURST_PCT` 太大         | -5 / -10                                      |
| 高速太灵敏             | `JOYSTICK_EXPO` 太小                                 | +0.3                                          |
| 高速太钝               | `JOYSTICK_EXPO` 太大                                 | -0.3                                          |
| 直走偏左/右            | `FRONT_BACK_COMPENSATION` 不准                       | ±0.02                                         |
| 平移时往前漂           | `STRAFE_VY_COUPLING` 太小                            | +0.02                                         |
| 起步某轮卡住           | `STARTUP_BURST_PCT` 太小或 `STARTUP_BURST_MS` 太短   | +10 / +50ms                                   |
| 操控有延迟             | 检查是否在用速度传感器                               | 确保用 `startup_burst` 而非速度反馈           |
| 旋转太快/太慢          | `OMEGA_EXPO` 不对                                    | 独立调，不与 `JOYSTICK_EXPO` 绑定             |
| 精细操作要么不动要么窜 | 缺乏精细模式，曲线抬升导致无法输出 1~15% 功率        | 启用 `FINE_CONTROL_ENABLE`，反复微调自动降速  |
| 精细模式不触发         | `FINE_CONTROL_ACTIVITY_MIN` 太高或 `WINDOW_MS` 太长  | ↓ `ACTIVITY_MIN` 到 2，↓ `WINDOW_MS` 到 300   |
| 低速巡航也被降速       | `FINE_CONTROL_ACTIVITY_MIN` 太低                     | ↑ `ACTIVITY_MIN` 到 5，确保只有反复调整才触发 |
| 精细模式下来回抖动     | `FINE_CONTROL_SPEED_SCALE` 太小 + 退出阈值太高       | ↑ `SPEED_SCALE` 到 0.40，↓ `EXIT_THRESHOLD`   |
| LED 显示 f 但速度没变  | `FINE_CONTROL_ENABLE` = False 或 `SPEED_SCALE` = 1.0 | 检查参数值                                    |
