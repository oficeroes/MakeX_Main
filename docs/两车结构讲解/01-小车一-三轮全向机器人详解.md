# 小車一 · 三輪全向機器人 —— 硬件與軟件搭配全解

> **主控代碼**：`mecanum_forward.py`（項目根目錄，Novapi / MicroPython）
> **底盤類型**：三輪 120° 對稱全向（omni），`trajectory_planner` 中的 `omni3` 配置
> **一句話定位**：一臺"多面手"得分車 —— 三條邊各掛一套任務設備，靠**換面**讓不同機構對準目標。
> 可 360° 全向移動 + 原地換 120° 正面 + 雙側升降夾取臂 + 收球/發射小球。

---

## 1. 硬件總覽（這輛車身上有什麼）

| 類別         | 數量 | 具體硬件                                               |
| ------------ | :--: | ------------------------------------------------------ |
| 驅動電機     |  3   | M1 / M2 / M3 —— **編碼電機**（帶角度反饋）+ **全向輪** |
| 升降臂電機   |  2   | M4 / M5 —— **編碼電機**，各驅動一條升降臂              |
| 夾爪舵機     | 1~3  | M6 端口鏈上的 **智能舵機**（INDEX1/2/3 三路）          |
| 收球電機     |  1   | DC1 —— **直流電機**（動力擴展板），驅動收球履帶        |
| 輔助出球電機 |  1   | DC2 —— **直流電機**（動力擴展板）                      |
| 發射電機     | 1~2  | BL1（/BL2）—— **無刷電機**（動力擴展板），高速發射小球 |
| 顯示屏       |  1   | **8×16 LED 點陣屏**（PORT2·INDEX1），唯一的用戶界面    |
| 遙控手柄     |  1   | MakeX 遊戲手柄（雙搖桿 + D-pad + 數字鍵 + L/R 鍵）     |
| 主控         |  1   | Novapi 主控板 + **動力擴展板**（給 DC/BL 供電驅動）    |

> **核心認知**：M1~M3 是"腳"，M4/M5+舵機是"手"，DC/BL 是"嘴"（收球/發射），LED 是"眼睛/屏幕"。
> 這臺車沒有普通屏幕也沒有喇叭，**代碼裏的 `print()` 上傳後完全看不到** —— 一切狀態提示都靠 LED 屏。

## 3. 底盤：硬件與運動學的搭配

### 3.1 輪子佈局與旋轉方向

```
        前進方向 (+Vy)
             ↑
      M1 ←──┼──→ M2        M1：前左輪（150° 位置）
             │              M2：前右輪（30° 位置）
             M3             M3：尾部輪（270° 位置）
```

三輪 120° 對稱全向：任意方向都能走（前進/後退/橫移/斜行/原地自旋），
沒有"車頭"的物理限制 —— 這正是它能"換面"的硬件前提。

### 3.2 逆運動學（軟件如何把搖桿變成三個輪子）

```python
def omni_kinematics(Vx, Vy, omega):
    M1 = -0.5*Vx - 0.866*Vy - omega
    M2 = -0.5*Vx + 0.866*Vy - omega
    M3 =  1.0*Vx           - omega
```

- `Vx`：橫向速度（+右），`Vy`：縱向速度（+前），`omega`：旋轉（+順時針）
- 任一電機算出來超過 ±100 時，**三路等比縮放**，保證方向不歪
- 三角函數值已預存成常量 `HALF=0.5` / `SQRT3_OVER_2=0.866`，省運行時計算

### 3.3 爲什麼是全向輪 + 編碼電機

- **全向輪**（輥子朝側向）：讓"橫移"成爲可能 —— 輪子側向不打滑，靠輥子滑走。
- **編碼電機**（能讀 `angle` 角度）：換面旋轉、自動程序都要靠它做**閉環**：
  - 編碼器把"轉了多少"變成數字，軟件據此判斷"到位了沒"
  - 關鍵換算常量：`ENCODER_TICKS_PER_CM = 23.476`（直行）、`TURN_TICKS_PER_DEG = 27.738`（旋轉）

## 4. "三面結構"：這臺車最獨特的硬件設計

因爲底盤是三角形，**三條邊 = 三個正面（Face）**，每條邊掛的設備不一樣：

```
          Face 0（默認，M1—M2 邊）── 收球/發射面
              ●────●
             ╱      ╲
        Face2      Face1
        (M3—M1)    (M2—M3)
        升降夾取面   升降夾取面
             ╲      ╱
              ●────●
```

| 面  | 硬件搭載                                          | 軟件裏的設備映射                                 |
| :-: | ------------------------------------------------- | ------------------------------------------------ |
|  0  | DC1 收球履帶 + DC2 出球 + BL1 無刷發射 + SV3 舵機 | 收球、發射、輔助                                 |
|  1  | 升降臂電機 M5（PID 索引1）+ 夾爪 SV1              | `_face_lift_motor[1]=1`，`_face_grip_servo[1]=0` |
|  2  | 升降臂電機 M4（PID 索引0）+ 夾爪 SV2              | `_face_lift_motor[2]=0`，`_face_grip_servo[2]=1` |

> 軟件裏用 `face`（0/1/2）變量表示"當前正面"，配套兩張映射表：
> `_face_lift_motor`（當前面用哪條升降臂）和 `_face_grip_servo`（當前面用哪個夾爪）。
> **換面 = 換座標系 + 換設備映射 + 車身物理旋轉 120°**，三者同步，見 §6。

### 4.1 面切換的硬件動作：車身自己轉 120°

- 車身結構對稱，物理上"哪條邊朝對手"都可以由程序決定。
- 但爲了**搖桿"往前推 = 朝當前正面走"**，軟件不能只記一個變量：
  前進向量要跟着正面的法線轉 —— 用 `FACE_ROTATIONS` 三張預計算旋轉矩陣做座標旋轉（避免每幀算三角函數）：

```python
# 代碼原樣（每一行 = 一個正面的 (c, ns, s, nc)，rotate_velocity 裏算：Vx'=c·Vx+ns·Vy, Vy'=s·Vx+nc·Vy）
COS120 = -0.5; SIN120 = 0.866
FACE_ROTATIONS = [
    (-1.0,   0.0,    0.0,  -1.0),    # Face0
    (COS120, -SIN120, SIN120, COS120), # Face1（相對 +120°）
    (COS120,  SIN120, -SIN120, COS120), # Face2（相對 -120°）
]
```

- Face1 / Face2 正是把搖桿向量旋轉 ±120° 的矩陣；Face0 是整體取反
  （把"搖桿軸 → 屏幕座標 → 物理電機方向"換算進默認正面，正負號與接線綁定，改接線需複覈）。
- 同時按 L1 時車身用**編碼器 PID 閉環**真的轉 120°（不是開環計時），
  因爲電池電壓、地面摩擦都會讓"同樣時間轉不同角度"，而編碼器以實際角度爲準。

## 5. 功能系統逐個拆解（硬件 ↔ 軟件怎麼搭配）

### 5.1 收球系統 —— DC1（直流電機）

```
按 N2（處於 Face0）→ DC1 = -100（收球履帶轉，把球捲進管道）
再按 N2           → DC1 = 0（停）
```

- DC1 是**唯一收球設備**，代碼裏 `DC_COLLECTOR_PORT='DC1'`、`DC_COLLECTOR_SPEED=-100`
- 球路：DC1 履帶收球 → 推入管道 → 管道上方 BL1 無刷高速旋轉把球打出去
- 軟件是"開關切換式"（toggle），不是按住才動

### 5.2 發射系統 —— BL1（無刷電機）

| 操作（Face0 下） | 行爲                                     |
| ---------------- | ---------------------------------------- |
| R2               | BL1 開/關（以當前 `BL_ACTION_SPEED` 轉） |
| D-pad ↑          | 發射速度 +5（上限 100）                  |
| D-pad ↓          | 發射速度 -5（下限 10）                   |
| N4               | DC2 出球輔助開/關（`DC2=100`）           |

- 無刷轉速極高，代碼通過 `power_expand_board.set_power('BL1', …)` 控速、`stop()` 停止
- 默認 `BL_ACTION_SPEED = 80`，主循環每幀把這個數字刷到 LED 上（`S80`）

### 5.3 升降臂系統 —— M4 / M5（編碼電機 + 位置 PID）

兩條升降臂是"手"，需要精確停在某個高度去夾東西，所以不能用開環功率，而是：

```
lift_pid_start(motor_idx, target_deg)      # 設定目標角度
   ↓ 每幀
lift_pid_tick(motor_idx)
   ├─ 讀編碼器 angle → 減零偏 → 算誤差
   ├─ PID(Kp=0.5, Ki=0.04, Kd=0.02) → 功率
   ├─ 接近目標走"餘弦減速"，末尾最小速度兜底（防爬不動）
   ├─ 堵轉檢測（編碼器不動 0.18s → 給一記猛推掙脫靜摩擦）
   ├─ 誤差<6° 且穩定 0.1s → set_power(0) 停電（蝸桿自鎖保持）
   └─ 4s 超時強制停
```

| 硬件事實                              | 軟件補償                                           |
| ------------------------------------- | -------------------------------------------------- |
| M5 是**反裝**（正功率方向與 M4 相反） | `LIFT_DIR=[1,-1]`：PID 輸出後按臂乘方向係數        |
| 編碼器讀數方向也可能相反              | `LIFT_ENCODER_SIGN=[1,-1]` 統一成"目標-當前"的誤差 |
| 每次斷電位置會丟                      | `_lift_zero_offset` 記錄零偏；N3/R1 觸發"砸底回零" |

- 檔位表 `DEBUG_LIFT_GEARS = [0, 315, 420, 480, 660, 1300]`，D-pad↑↓/N2 在檔位間切換
- D-pad←→ 在檔位基礎上 ±30° 微調（`LIFT_FINE_STEP=30`）
- 上電行爲（當前代碼）：啓動後把兩臂 PID 抬到 700° 目標，LED 常顯 `Main`

### 5.4 夾爪系統 —— M6 智能舵機（開關式夾緊/鬆開）

舵機夾緊的本質是"給一個方向的功率讓它一直夾"，軟件用狀態機控制它何時夾、何時松：

```
R2（Face1/2）→ 夾緊：給 GRIP_CLOSE_POWER=-100（負方向=夾）
  每幀檢查（_grip_tick_all）：
    ├─ 角度到該路限位 SERVO_MAX_ANGLE → 進入保持
    └─ 夾了 5s 超時 → 進入保持
再按 R2 → 鬆開：GRIP_RELEASE_POWER=60 持續 0.8s → set_power(0) 回全開位
```

- 每路舵機一個獨立狀態機（`_grip_active/_grip_closing/_grip_hold/_grip_releasing` 數組，索引 0/1/2 = SV1/SV2/SV3）
- 方向鐵律：**0°=全開位，夾緊方向寫死爲負功率**（`GRIP_CLOSE_POWER=-100`），嚴禁把"夾"做成正方向（會撐爆夾爪）
- 角度硬限位 `SERVO_MAX_ANGLE=[480,480,290]`（各臂機械極限不同），到限位即不再判定"繼續夾"

> ⚠️ 說明：更早版本文檔描述過"速度堵轉檢測=夾到物體自動停"的自適應方案，
> **當前代碼裏該檢測已不在夾緊迴路中**（`GRIP_SPEED_THRESHOLD` 等常量僅保留未用），
> 現在是"限位 / 超時 → 保持，再按 R2 鬆開"的簡化邏輯 —— 以代碼爲準。

### 5.5 LED 屏 —— 唯一的"屏幕"

- 接 PORT2·INDEX1，只能顯示 ASCII（英文/數字/符號），不支持中文
- 軟件裏它是**狀態心跳**：
  `Main`（主界面）、`Ph1/Ph2`（比賽階段選擇）、`SV1/SV2`（舵機調試）、`Done`（自動結束）、
  `Stop`（手動中斷）、`Sxx`（每幀刷新當前發射速度）等

## 6. 軟件總體架構（這些硬件是怎麼被"編排"起來的）

### 6.1 一個主循環，四個模式（按優先級）

```
while True:
  ① 比賽階段選擇模式（≡ 鍵進入）      ← 最高級：上場前選 Ph1/Ph2，還能進舵機調試
  ② 換面旋轉中（face_rotating）        ← L1 按下後車身轉 120°，邊轉邊可疊加連續換面
  ③ 自動程序（auto_mode，+ 鍵進入）    ← 整條 AUTO_SEQUENCE 跑完自動退出；N4 中斷
  ④ 正常遙控模式（默認）               ← 手動全功能操作
```

- 主循環節拍 `_LD = 0.02s`（50Hz）
- 所有按鍵用**邊沿觸發**（`cur_X and not last_X`），避免按住時每幀重複執行
- 每幀末尾統一 `last_* = cur_*` 更新邊沿記憶

### 6.2 遙控信號鏈：搖桿 → 輪子（7 步）

```
搖桿原始值 (-100~100)
 ① apply_dead_zone()      死區過濾：|x|<3 歸零（防中位抖動）
 ② apply_response_curve() 兩段響應曲線：低段線性(0~25%→0~18%) + 高段指數(1.7)
 ③ × SPEED_SCALE=0.85     全侷限速
 ④ Vy = -Ly               （搖桿上推=屏幕上前）
 ⑤ rotate_velocity()      按當前 face 把移動向量旋轉到"當前正面"
 ⑥ Vy ×= VY_BOOST=1.4     縱向增強（三輪前進只有兩個輪主力，摩擦補償）
 ⑦ omni_kinematics() → M1/M2/M3.set_power()
```

### 6.3 自動程序：預錄動作序列

- 按 `+` 觸發，`AUTO_SEQUENCE` 是"劇本"，逐條執行：
  `enc_move_s`（編碼器直/斜行，帶加速/減速弧）、`enc_rot`（編碼器自旋）、
  `open_move`（開環走+航向糾偏）、`lift`/`lift_async`（升降臂 PID）、`grip`（夾/放）、
  `motor`/`dc_motor`（任意電機開指定功率）、`delay`、`face_rot`（換面）、`servo`、`enc_stop`
- 這類序列通常由 `trajectory_planner` GUI 畫出來導出，也可以手寫
- 自動期間遙控全禁用，跑完 LED 顯 `Done`；N4 隨時中斷（顯 `Stop`）

### 6.4 比賽階段（match_phase）：上場的"開局設置"

按 ≡ 進入階段選擇：

| 階段 | 按鍵             | 含義                                                |
| :--: | ---------------- | --------------------------------------------------- |
| Ph1  | N2 選中、R1 確認 | 默認雙面雙臂配置（Face1=M5+SV1，Face2=M4+SV2）      |
| Ph2  | N4 選中、R1 確認 | 單臂配置：只用 Face2 的 M4 臂 + SV3，上場自動抬到頂 |

> 階段選擇裏按 L1 可進"舵機調試"：Rx 控制舵機功率、L1 換 SV1/SV2、`+` 把當前舵機設零點（`set_zero`）。

### 6.5 按鍵速查表（正常遙控，按當前面區分）

| 右搖桿  | 原地自旋                 | 同左                  | 同左                  |
| L1      | 切到下一面 + 車身轉 120° | 同左                  | 同左                  |
| N2      | DC1 收球 開/關           | 升降臂(M5) 檔位+1     | 升降臂(M4) 檔位+1     |
| R2      | BL1 發射 開/關           | SV1 夾緊/鬆開         | SV2 夾緊/鬆開         |
| D-pad ↑ | 發射速度 +5              | 檔位 +1               | 檔位 +1               |
| D-pad ↓ | 發射速度 -5              | 檔位 -1               | 檔位 -1               |

## 8. 軟件搭配上的"鐵律"（改代碼前必讀）

1. **LED 是唯一輸出**：機器人上沒有終端，`print()` 看不到。本文件已把 `print` 替換成空函數 `_safe_print` 省內存；狀態提示必須走 `__led.show()`。
2. **字節碼上限極緊**：Novapi 限制的是**編譯後字節碼**而非文件大小。實測餘量只有 ~150–200 B —— 禁止新增大型 per-frame 函數；加功能一次只加一個，燒錄後必須實測遙控有反應（`ast.parse` 通過 ≠ 能跑）。詳見 `NOVAPI_BYTECODE_LIMIT.md`。
3. **舵機方向**：0°=全開，負角度=夾緊；角度嚴禁超機械極限，否則齒輪掃齒。
4. **升降臂到位必須停電**：PID 到位穩定後 `set_power(0)`，靠蝸桿自鎖保持，長時間通電會過熱。
5. **代碼裏遺留的 `try/except`**：項目規範要求避免（歷史遺留仍在文件裏，改動時儘量不新增）。
6. 端子上電順序、機械歸零等物理細節，改動接線/裝夾後要在場上實測驗證方向。
