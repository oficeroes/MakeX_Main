# 小车一 · 三轮全向机器人 —— 硬件与软件搭配全解

> **主控代码**：`mecanum_forward.py`（项目根目录，Novapi / MicroPython）
> **底盘类型**：三轮 120° 对称全向（omni），`trajectory_planner` 中的 `omni3` 配置
> **一句话定位**：一台"多面手"得分车 —— 三条边各挂一套任务设备，靠**换面**让不同机构对准目标。
> 可 360° 全向移动 + 原地换 120° 正面 + 双侧升降夹取臂 + 收球/发射小球。

---

## 1. 硬件总览（这辆车身上有什么）

| 类别         | 数量 | 具体硬件                                               |
| ------------ | :--: | ------------------------------------------------------ |
| 驱动电机     |  3   | M1 / M2 / M3 —— **编码电机**（带角度反馈）+ **全向轮** |
| 升降臂电机   |  2   | M4 / M5 —— **编码电机**，各驱动一条升降臂              |
| 夹爪舵机     | 1~3  | M6 端口链上的 **智能舵机**（INDEX1/2/3 三路）          |
| 收球电机     |  1   | DC1 —— **直流电机**（动力扩展板），驱动收球履带        |
| 辅助出球电机 |  1   | DC2 —— **直流电机**（动力扩展板）                      |
| 发射电机     | 1~2  | BL1（/BL2）—— **无刷电机**（动力扩展板），高速发射小球 |
| 显示屏       |  1   | **8×16 LED 点阵屏**（PORT2·INDEX1），唯一的用户界面    |
| 遥控手柄     |  1   | MakeX 游戏手柄（双摇杆 + D-pad + 数字键 + L/R 键）     |
| 主控         |  1   | Novapi 主控板 + **动力扩展板**（给 DC/BL 供电驱动）    |

> **核心认知**：M1~M3 是"脚"，M4/M5+舵机是"手"，DC/BL 是"嘴"（收球/发射），LED 是"眼睛/屏幕"。
> 这台车没有普通屏幕也没有喇叭，**代码里的 `print()` 上传后完全看不到** —— 一切状态提示都靠 LED 屏。

## 2. 端口接线表（硬件 ↔ 代码对象一一对应）

代码在文件顶部用 `encoder_motor_class / led_matrix_class / smartservo_class / power_expand_board` 初始化全部外设：

```python
__led      = led_matrix_class('PORT2', 'INDEX1')     # 8×16 LED 屏
__motor_M1 = encoder_motor_class('M1', 'INDEX1')     # 前左全向轮
__motor_M2 = encoder_motor_class('M2', 'INDEX1')     # 前右全向轮
__motor_M3 = encoder_motor_class('M3', 'INDEX1')     # 尾部全向轮
__motor_M4 = encoder_motor_class('M4', 'INDEX1')     # 升降臂 A（PID 电机 0）
__motor_M5 = encoder_motor_class('M5', 'INDEX1')     # 升降臂 B（PID 电机 1）
__servo_1  = smartservo_class('M6', 'INDEX1')        # 夹爪舵机 SV1
__servo_2  = smartservo_class('M6', 'INDEX2')        # 夹爪舵机 SV2
__servo_3  = smartservo_class('M6', 'INDEX3')        # 夹爪舵机 SV3（第三路，备用/收球面用）
```

| 端口         | 通道     | 硬件                 | 代码对象 / API                           | 用途             |
| ------------ | -------- | -------------------- | ---------------------------------------- | ---------------- |
| M1 INDEX1    | 编码电机 | 前左全向轮           | `__motor_M1.set_power()`                 | 底盘驱动         |
| M2 INDEX1    | 编码电机 | 前右全向轮           | `__motor_M2`                             | 底盘驱动         |
| M3 INDEX1    | 编码电机 | 尾部全向轮           | `__motor_M3`                             | 底盘驱动         |
| M4 INDEX1    | 编码电机 | 升降臂 A             | `__motor_M4`（PID 索引 0）               | 升降（位置闭环） |
| M5 INDEX1    | 编码电机 | 升降臂 B（**反装**） | `__motor_M5`（PID 索引 1）               | 升降（位置闭环） |
| M6 INDEX1    | 智能舵机 | 夹爪舵机 SV1         | `__servo_1`                              | 夹取/松开        |
| M6 INDEX2    | 智能舵机 | 夹爪舵机 SV2         | `__servo_2`                              | 夹取/松开        |
| M6 INDEX3    | 智能舵机 | 夹爪舵机 SV3         | `__servo_3`                              | 收球面辅助动作   |
| 扩展板 DC1   | 直流电机 | 收球履带             | `power_expand_board.set_power('DC1', …)` | 收球             |
| 扩展板 DC2   | 直流电机 | 辅助出球/推球        | `set_power('DC2', …)`                    | 出球辅助         |
| 扩展板 BL1   | 无刷电机 | 发射电机（左/主）    | `set_power('BL1', …)` / `stop('BL1')`    | 发射小球         |
| 扩展板 BL2   | 无刷电机 | 发射电机（右/备）    | `stop_all_motors()` 中一并停止           | 发射（备用）     |
| PORT2 INDEX1 | 点阵屏   | 8×16 LED             | `__led.show('…')`                        | 唯一人机界面     |

> **软件上的"端口链"概念**：Novapi 的 `M6` 是一个物理口，可以串多个同类型模块，
> 用 `INDEX1/INDEX2/INDEX3` 区分 —— 所以"1 个舵机口 = 3 个舵机实例"。
> 无刷电机 BL1/BL2 没有独立对象，统一走 `power_expand_board` 扩展板 API。

## 3. 底盘：硬件与运动学的搭配

### 3.1 轮子布局与旋转方向

```
        前进方向 (+Vy)
             ↑
      M1 ←──┼──→ M2        M1：前左轮（150° 位置）
             │              M2：前右轮（30° 位置）
             M3             M3：尾部轮（270° 位置）
```

三轮 120° 对称全向：任意方向都能走（前进/后退/横移/斜行/原地自旋），
没有"车头"的物理限制 —— 这正是它能"换面"的硬件前提。

### 3.2 逆运动学（软件如何把摇杆变成三个轮子）

```python
def omni_kinematics(Vx, Vy, omega):
    M1 = -0.5*Vx - 0.866*Vy - omega
    M2 = -0.5*Vx + 0.866*Vy - omega
    M3 =  1.0*Vx           - omega
```

- `Vx`：横向速度（+右），`Vy`：纵向速度（+前），`omega`：旋转（+顺时针）
- 任一电机算出来超过 ±100 时，**三路等比缩放**，保证方向不歪
- 三角函数值已预存成常量 `HALF=0.5` / `SQRT3_OVER_2=0.866`，省运行时计算

### 3.3 为什么是全向轮 + 编码电机

- **全向轮**（辊子朝侧向）：让"横移"成为可能 —— 轮子侧向不打滑，靠辊子滑走。
- **编码电机**（能读 `angle` 角度）：换面旋转、自动程序都要靠它做**闭环**：
  - 编码器把"转了多少"变成数字，软件据此判断"到位了没"
  - 关键换算常量：`ENCODER_TICKS_PER_CM = 23.476`（直行）、`TURN_TICKS_PER_DEG = 27.738`（旋转）

## 4. "三面结构"：这台车最独特的硬件设计

因为底盘是三角形，**三条边 = 三个正面（Face）**，每条边挂的设备不一样：

```
          Face 0（默认，M1—M2 边）── 收球/发射面
              ●────●
             ╱      ╲
        Face2      Face1
        (M3—M1)    (M2—M3)
        升降夹取面   升降夹取面
             ╲      ╱
              ●────●
```

| 面  | 硬件搭载                                          | 软件里的设备映射                                 |
| :-: | ------------------------------------------------- | ------------------------------------------------ |
|  0  | DC1 收球履带 + DC2 出球 + BL1 无刷发射 + SV3 舵机 | 收球、发射、辅助                                 |
|  1  | 升降臂电机 M5（PID 索引1）+ 夹爪 SV1              | `_face_lift_motor[1]=1`，`_face_grip_servo[1]=0` |
|  2  | 升降臂电机 M4（PID 索引0）+ 夹爪 SV2              | `_face_lift_motor[2]=0`，`_face_grip_servo[2]=1` |

> 软件里用 `face`（0/1/2）变量表示"当前正面"，配套两张映射表：
> `_face_lift_motor`（当前面用哪条升降臂）和 `_face_grip_servo`（当前面用哪个夹爪）。
> **换面 = 换坐标系 + 换设备映射 + 车身物理旋转 120°**，三者同步，见 §6。

### 4.1 面切换的硬件动作：车身自己转 120°

- 车身结构对称，物理上"哪条边朝对手"都可以由程序决定。
- 但为了**摇杆"往前推 = 朝当前正面走"**，软件不能只记一个变量：
  前进向量要跟着正面的法线转 —— 用 `FACE_ROTATIONS` 三张预计算旋转矩阵做坐标旋转（避免每帧算三角函数）：

```python
# 代码原样（每一行 = 一个正面的 (c, ns, s, nc)，rotate_velocity 里算：Vx'=c·Vx+ns·Vy, Vy'=s·Vx+nc·Vy）
COS120 = -0.5; SIN120 = 0.866
FACE_ROTATIONS = [
    (-1.0,   0.0,    0.0,  -1.0),    # Face0
    (COS120, -SIN120, SIN120, COS120), # Face1（相对 +120°）
    (COS120,  SIN120, -SIN120, COS120), # Face2（相对 -120°）
]
```

- Face1 / Face2 正是把摇杆向量旋转 ±120° 的矩阵；Face0 是整体取反
  （把"摇杆轴 → 屏幕坐标 → 物理电机方向"换算进默认正面，正负号与接线绑定，改接线需复核）。
- 同时按 L1 时车身用**编码器 PID 闭环**真的转 120°（不是开环计时），
  因为电池电压、地面摩擦都会让"同样时间转不同角度"，而编码器以实际角度为准。

## 5. 功能系统逐个拆解（硬件 ↔ 软件怎么搭配）

### 5.1 收球系统 —— DC1（直流电机）

```
按 N2（处于 Face0）→ DC1 = -100（收球履带转，把球卷进管道）
再按 N2           → DC1 = 0（停）
```

- DC1 是**唯一收球设备**，代码里 `DC_COLLECTOR_PORT='DC1'`、`DC_COLLECTOR_SPEED=-100`
- 球路：DC1 履带收球 → 推入管道 → 管道上方 BL1 无刷高速旋转把球打出去
- 软件是"开关切换式"（toggle），不是按住才动

### 5.2 发射系统 —— BL1（无刷电机）

| 操作（Face0 下） | 行为                                     |
| ---------------- | ---------------------------------------- |
| R2               | BL1 开/关（以当前 `BL_ACTION_SPEED` 转） |
| D-pad ↑          | 发射速度 +5（上限 100）                  |
| D-pad ↓          | 发射速度 -5（下限 10）                   |
| N4               | DC2 出球辅助开/关（`DC2=100`）           |

- 无刷转速极高，代码通过 `power_expand_board.set_power('BL1', …)` 控速、`stop()` 停止
- 默认 `BL_ACTION_SPEED = 80`，主循环每帧把这个数字刷到 LED 上（`S80`）

### 5.3 升降臂系统 —— M4 / M5（编码电机 + 位置 PID）

两条升降臂是"手"，需要精确停在某个高度去夹东西，所以不能用开环功率，而是：

```
lift_pid_start(motor_idx, target_deg)      # 设定目标角度
   ↓ 每帧
lift_pid_tick(motor_idx)
   ├─ 读编码器 angle → 减零偏 → 算误差
   ├─ PID(Kp=0.5, Ki=0.04, Kd=0.02) → 功率
   ├─ 接近目标走"余弦减速"，末尾最小速度兜底（防爬不动）
   ├─ 堵转检测（编码器不动 0.18s → 给一记猛推挣脱静摩擦）
   ├─ 误差<6° 且稳定 0.1s → set_power(0) 停电（蜗杆自锁保持）
   └─ 4s 超时强制停
```

| 硬件事实                              | 软件补偿                                           |
| ------------------------------------- | -------------------------------------------------- |
| M5 是**反装**（正功率方向与 M4 相反） | `LIFT_DIR=[1,-1]`：PID 输出后按臂乘方向系数        |
| 编码器读数方向也可能相反              | `LIFT_ENCODER_SIGN=[1,-1]` 统一成"目标-当前"的误差 |
| 每次断电位置会丢                      | `_lift_zero_offset` 记录零偏；N3/R1 触发"砸底回零" |

- 档位表 `DEBUG_LIFT_GEARS = [0, 315, 420, 480, 660, 1300]`，D-pad↑↓/N2 在档位间切换
- D-pad←→ 在档位基础上 ±30° 微调（`LIFT_FINE_STEP=30`）
- 上电行为（当前代码）：启动后把两臂 PID 抬到 700° 目标，LED 常显 `Main`

### 5.4 夹爪系统 —— M6 智能舵机（开关式夹紧/松开）

舵机夹紧的本质是"给一个方向的功率让它一直夹"，软件用状态机控制它何时夹、何时松：

```
R2（Face1/2）→ 夹紧：给 GRIP_CLOSE_POWER=-100（负方向=夹）
  每帧检查（_grip_tick_all）：
    ├─ 角度到该路限位 SERVO_MAX_ANGLE → 进入保持
    └─ 夹了 5s 超时 → 进入保持
再按 R2 → 松开：GRIP_RELEASE_POWER=60 持续 0.8s → set_power(0) 回全开位
```

- 每路舵机一个独立状态机（`_grip_active/_grip_closing/_grip_hold/_grip_releasing` 数组，索引 0/1/2 = SV1/SV2/SV3）
- 方向铁律：**0°=全开位，夹紧方向写死为负功率**（`GRIP_CLOSE_POWER=-100`），严禁把"夹"做成正方向（会撑爆夹爪）
- 角度硬限位 `SERVO_MAX_ANGLE=[480,480,290]`（各臂机械极限不同），到限位即不再判定"继续夹"

> ⚠️ 说明：更早版本文档描述过"速度堵转检测=夹到物体自动停"的自适应方案，
> **当前代码里该检测已不在夹紧回路中**（`GRIP_SPEED_THRESHOLD` 等常量仅保留未用），
> 现在是"限位 / 超时 → 保持，再按 R2 松开"的简化逻辑 —— 以代码为准。

### 5.5 LED 屏 —— 唯一的"屏幕"

- 接 PORT2·INDEX1，只能显示 ASCII（英文/数字/符号），不支持中文
- 软件里它是**状态心跳**：
  `Main`（主界面）、`Ph1/Ph2`（比赛阶段选择）、`SV1/SV2`（舵机调试）、`Done`（自动结束）、
  `Stop`（手动中断）、`Sxx`（每帧刷新当前发射速度）等

## 6. 软件总体架构（这些硬件是怎么被"编排"起来的）

### 6.1 一个主循环，四个模式（按优先级）

```
while True:
  ① 比赛阶段选择模式（≡ 键进入）      ← 最高级：上场前选 Ph1/Ph2，还能进舵机调试
  ② 换面旋转中（face_rotating）        ← L1 按下后车身转 120°，边转边可叠加连续换面
  ③ 自动程序（auto_mode，+ 键进入）    ← 整条 AUTO_SEQUENCE 跑完自动退出；N4 中断
  ④ 正常遥控模式（默认）               ← 手动全功能操作
```

- 主循环节拍 `_LD = 0.02s`（50Hz）
- 所有按键用**边沿触发**（`cur_X and not last_X`），避免按住时每帧重复执行
- 每帧末尾统一 `last_* = cur_*` 更新边沿记忆

### 6.2 遥控信号链：摇杆 → 轮子（7 步）

```
摇杆原始值 (-100~100)
 ① apply_dead_zone()      死区过滤：|x|<3 归零（防中位抖动）
 ② apply_response_curve() 两段响应曲线：低段线性(0~25%→0~18%) + 高段指数(1.7)
 ③ × SPEED_SCALE=0.85     全局限速
 ④ Vy = -Ly               （摇杆上推=屏幕上前）
 ⑤ rotate_velocity()      按当前 face 把移动向量旋转到"当前正面"
 ⑥ Vy ×= VY_BOOST=1.4     纵向增强（三轮前进只有两个轮主力，摩擦补偿）
 ⑦ omni_kinematics() → M1/M2/M3.set_power()
```

### 6.3 自动程序：预录动作序列

- 按 `+` 触发，`AUTO_SEQUENCE` 是"剧本"，逐条执行：
  `enc_move_s`（编码器直/斜行，带加速/减速弧）、`enc_rot`（编码器自旋）、
  `open_move`（开环走+航向纠偏）、`lift`/`lift_async`（升降臂 PID）、`grip`（夹/放）、
  `motor`/`dc_motor`（任意电机开指定功率）、`delay`、`face_rot`（换面）、`servo`、`enc_stop`
- 这类序列通常由 `trajectory_planner` GUI 画出来导出，也可以手写
- 自动期间遥控全禁用，跑完 LED 显 `Done`；N4 随时中断（显 `Stop`）

### 6.4 比赛阶段（match_phase）：上场的"开局设置"

按 ≡ 进入阶段选择：

| 阶段 | 按键             | 含义                                                |
| :--: | ---------------- | --------------------------------------------------- |
| Ph1  | N2 选中、R1 确认 | 默认双面双臂配置（Face1=M5+SV1，Face2=M4+SV2）      |
| Ph2  | N4 选中、R1 确认 | 单臂配置：只用 Face2 的 M4 臂 + SV3，上场自动抬到顶 |

> 阶段选择里按 L1 可进"舵机调试"：Rx 控制舵机功率、L1 换 SV1/SV2、`+` 把当前舵机设零点（`set_zero`）。

### 6.5 按键速查表（正常遥控，按当前面区分）

| 键      | Face 0（收球面）         | Face 1（臂= M5+SV1）  | Face 2（臂= M4+SV2）  |
| ------- | ------------------------ | --------------------- | --------------------- |
| 左摇杆  | 全向移动（方向=当前面）  | 同左                  | 同左                  |
| 右摇杆  | 原地自旋                 | 同左                  | 同左                  |
| L1      | 切到下一面 + 车身转 120° | 同左                  | 同左                  |

| D-pad ↑ | 发射速度 +5              | 档位 +1               | 档位 +1               |

## 7. 关键常量速查（想调手感/行为改这里）

| 类别 | 常量                     |          默认值          | 说明                       |
| ---- | ------------------------ | :----------------------: | -------------------------- |
| 手感 | `SPEED_SCALE`            |           0.85           | 全局速度倍率               |

## 8. 软件搭配上的"铁律"（改代码前必读）

1. **LED 是唯一输出**：机器人上没有终端，`print()` 看不到。本文件已把 `print` 替换成空函数 `_safe_print` 省内存；状态提示必须走 `__led.show()`。
2. **字节码上限极紧**：Novapi 限制的是**编译后字节码**而非文件大小。实测余量只有 ~150–200 B —— 禁止新增大型 per-frame 函数；加功能一次只加一个，烧录后必须实测遥控有反应（`ast.parse` 通过 ≠ 能跑）。详见 `NOVAPI_BYTECODE_LIMIT.md`。
3. **舵机方向**：0°=全开，负角度=夹紧；角度严禁超机械极限，否则齿轮扫齿。
4. **升降臂到位必须停电**：PID 到位稳定后 `set_power(0)`，靠蜗杆自锁保持，长时间通电会过热。
5. **代码里遗留的 `try/except`**：项目规范要求避免（历史遗留仍在文件里，改动时尽量不新增）。
6. 端子上电顺序、机械归零等物理细节，改动接线/装夹后要在场上实测验证方向。
