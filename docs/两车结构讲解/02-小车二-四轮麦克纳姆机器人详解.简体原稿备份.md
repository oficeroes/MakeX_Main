# 小车二 · 四轮麦克纳姆（X 型）机器人 —— 硬件与软件搭配全解

> **主控代码**：`mecanum_drive.py`（项目根目录，Novapi / MicroPython）
> **底盘类型**：四轮 X 型麦克纳姆（mecanum），`trajectory_planner` 中的 `mecanum_4w` 配置
> **一句话定位**：四轮麦克纳姆全向底盘 + 一整套"**收球 → 滚球 → 发射**"的连续进球流水线。

## 1. 硬件总览（这辆车身上有什么）

| 类别     | 数量 | 具体硬件                                               |
| -------- | :--: | ------------------------------------------------------ |
| 驱动电机 |  4   | M1 / M2 / M3 / M4 —— **编码电机** + **麦克纳姆轮**     |
| 滚球电机 |  1   | M5 —— **编码电机**，负责把球滚动/推送到发射位          |
| 执行舵机 |  2   | M6 端口链 **智能舵机** SV1（INDEX1）、SV2（INDEX2）    |
| 收球电机 | 1~3  | DC1 / DC2（/DC3）—— **直流电机**（动力扩展板）收球履带 |
| 发射电机 |  2   | BL1 / BL2 —— **无刷电机**（动力扩展板）高速发射        |
| 显示屏   |  1   | **8×16 LED 点阵屏**（接在 PORT3·INDEX1）               |
| 遥控手柄 |  1   | MakeX 游戏手柄                                         |
| 主控     |  1   | Novapi 主控板 + **动力扩展板**（DC/BL 都挂在扩展板上） |

> **核心认知**：M1~M4 是"脚"，M5+DC1~DC3 是"消化道"（收球→滚球），BL1/BL2+舵机是"嘴"（发射）。
> 小车一靠"换面"切换任务，小车二靠"多个执行机构同时/分时工作"完成一条进球流水线。

## 2. 端口接线表（硬件 ↔ 代码对象一一对应）

```python
__motor_M1 = encoder_motor_class("M1", "INDEX1")   # 前左轮 FL
__motor_M2 = encoder_motor_class("M2", "INDEX1")   # 前右轮 FR（反接）
__motor_M3 = encoder_motor_class("M3", "INDEX1")   # 后左轮 BL
__motor_M4 = encoder_motor_class("M4", "INDEX1")   # 后右轮 BR（反接）
__motor_M5 = encoder_motor_class("M5", "INDEX1")   # 滚球编码电机

__servo_1  = smartservo_class("M6", "INDEX1")      # 舵机 SV1
__servo_2  = smartservo_class("M6", "INDEX2")      # 舵机 SV2
# DC1/DC2/DC3、BL1/BL2 无对象，统一走 power_expand_board API
```

| 端口         | 通道     | 硬件               | 代码对象 / API                              | 用途         |
| ------------ | -------- | ------------------ | ------------------------------------------- | ------------ |

| M2 INDEX1    | 编码电机 | 前右轮 FR（反接）  | `__motor_M2`                                | 底盘驱动     |
| M3 INDEX1    | 编码电机 | 后左轮 BL          | `__motor_M3`                                | 底盘驱动     |
| M4 INDEX1    | 编码电机 | 后右轮 BR（反接）  | `__motor_M4`                                | 底盘驱动     |
| M5 INDEX1    | 编码电机 | 滚球电机           | `__motor_M5`                                | 滚球/送球    |
| M6 INDEX1    | 智能舵机 | 舵机 SV1           | `__servo_1.move_to(SERVO1_ACTION_ANGLE, …)` | 与 BL2 联动  |
| M6 INDEX2    | 智能舵机 | 舵机 SV2           | `__servo_2.move_to(SERVO2_ACTION_ANGLE, …)` | 与 BL1 联动  |

| 扩展板 DC3   | 直流电机 | 第三路直流（振荡） | `set_power("DC3", …)`（D-pad← 绑振荡）      | 防卡/吐球等  |

| 扩展板 BL2   | 无刷电机 | 发射电机 2         | `set_power("BL2", …)` / `stop("BL2")`       | 发射         |
| PORT3 INDEX1 | 点阵屏   | 8×16 LED           | `__led.show("…")`                           | 唯一人机界面 |

## 3. 底盘：硬件与运动学的搭配

### 3.2 逆运动学 + 反接补偿（硬件接反，软件兜底）

```python
def mecanum_kinematics(Vx, Vy, omega):
    M1 =  Vx + Vy + omega
    M2 = -Vx + Vy - omega
    M3 = -Vx + Vy + omega
    M4 =  Vx + Vy - omega
    M2 = -M2          # ← M2/FR 电机物理反接，软件取反
    M4 = -M4          # ← M4/BR 电机物理反接，软件取反
```

- **硬件事实**：M2 和 M4 两台电机是反向接线（省事/走线），
  软件在运动学里直接取反，让"正功率=前进"的世界观统一。
- 内嵌三组重量/装配补偿（软开关，默认部分开启）：
  - `FRONT_BACK_COMPENSATION`：前后轮出力不均补偿（当前 0.0）
  - `ROTATION_BALANCE`：旋转时前后均衡（当前 0.0）
  - `STRAFE_VY_COUPLING`：纯横移时会向前漂，按 |Vx| 减一点 Vy（当前 0.02）
- 任一电机超 ±100 → 四轮等比缩放，方向不变。

### 3.3 方向校准（接线错了不用改线，改常量）

| 常量           | 当前值 | 作用                                       |
| -------------- | :----: | ------------------------------------------ |
| `INVERT_VX`    | False  | 左右反了 → True                            |
| `INVERT_VY`    |  True  | 前后反了 → True（当前已反）                |
| `INVERT_OMEGA` |  True  | 旋转方向反了 → 取反                        |
| `face_flipped` | False  | L1 键运行时把前后左右整体取反（正开/倒开） |

> 遥控信号链（与小车一相同的两段式响应曲线，本车拐点用 20）：
> `死区(3) → 响应曲线(低段线性/高段指数) → ×SPEED_SCALE(0.65) → INVERT_* → face_flipped → 运动学 → set_power`

## 4. 功能系统逐个拆解（硬件 ↔ 软件怎么搭配）

### 4.1 收球 —— DC1 / DC2（直流履带）+ 滚球 M5

代码把这几个设备绑成两组"联动动作"，按一个键同时驱动多个电机：

| 按键 | 软件动作                           | 硬件效果（按当前代码设定）             |
| :--: | ---------------------------------- | -------------------------------------- |
|  N2  | `M5=-80` + `DC1=-100` + `DC2=-100` | 双履带收球 + 滚球电机反转向内送        |
|  N4  | `M5=+80` + `DC2=+100`              | 滚球电机正向 + DC2 正向（出/送球方向） |

- N2 / N4 互斥：开 N2 会自动关 N4，反之亦然
- `DC_COLLECTOR_SPEED = 100`（基础转速常量，实际按上面组合值使用）
- 自动程序里也能逐台驱动：`('dc_motor','DC1',-86)`、`('motor','M5',-66)` 等

> 具体每台电机正负号代表"收"还是"吐"，取决于机械装配方向 ——
> 代码只是当前标定值，**换机构后必须在场上实测确认方向**。

### 4.2 发射 —— BL1 / BL2（无刷电机）+ 联动舵机 SV1 / SV2

|  按键   | 软件动作                                         | 说明              |
| :-----: | ------------------------------------------------ | ----------------- |
|   L2    | 切换 BL1 开/关（与 BL2 互斥）                    | 开 BL1 自动关 BL2 |
|   R2    | 切换 BL2 开/关（与 BL1 互斥）                    | 开 BL2 自动关 BL1 |
| D-pad ↑ | 发射速度在预设 `[45,50,60]` 循环上调             | `BL_ACTION_SPEED` |
| D-pad ↓ | 预设循环下调                                     |                   |
|   N1    | **触发与"正在转的那个无刷"配对的舵机做一次击发** | 见下方交叉映射    |

**舵机与无刷是交叉配对的**（代码里的实际逻辑）：

| 当前状态           | N1 触发哪个舵机 | 动作                               |
| ------------------ | :-------------: | ---------------------------------- |
| BL1 在转（BL2 停） |       SV2       | `move_to(SERVO2_ACTION_ANGLE=38)`  |
| BL2 在转（BL1 停） |       SV1       | `move_to(SERVO1_ACTION_ANGLE=-38)` |
| 两个都没转         |    （拒绝）     | LED 显示 `LOCK`，舵机被锁住不动作  |

- 动作角度 `SERVO1_ACTION_ANGLE=-38` / `SERVO2_ACTION_ANGLE=38`（方向相反的两侧机构）
- 舵机以 `SERVO_ACTION_SPEED=50` 摆到角度后，延时 `SERVO_RETURN_DELAY=0.18s` **自动回中 0°**
- 用途是配合无刷"推/拨"一下球，形成发射动作；**无刷没开时按 N1 无效（防误击发）**

### 4.3 第三路直流 DC3 —— 振荡

| 按键    | 软件动作                                             |
| ------- | ---------------------------------------------------- |
| D-pad ← | DC3 振荡开关：开 = 每 0.5s 在 +100 / -100 间翻转一次 |

- 用途：让第三路直流小幅度往复摆动（防卡球/疏导等），具体看装配
- 再按一次 D-pad← 停止

### 4.4 L1 —— "车头翻转"（纯软件，不动硬件）

- 前后左右完全对称的车没有"面"，但操作者绕到另一侧时方向会反
- L1 切换 `face_flipped`：把 `Vx`、`Vy` 整体取反 = 正开 ↔ 倒开
- 纯软件映射，车身不转、电机不倒转方向之外的事

### 4.5 LED 屏 —— 状态心跳

- 接 **PORT3·INDEX1**（与小车一的 PORT2 不同！两车各占一个口）
- 常显 `Sxx`（当前发射速度）；特殊状态：`LOCK`（无刷没开按 N1）、`Main`、调试时的电机名 `M1`…`BL2`、`SV1` 等

## 5. 软件总体架构（这些硬件是怎么被"编排"起来的）

### 5.1 一个主循环，三种模式

```
while True:
  ① 自动程序（auto_mode，+ 键进入）      ← 最高优先
  ② 调试模式（debug_mode，≡ 键进入）      ← 逐电机/舵机/无刷测试
  ③ 正常遥控模式（默认）
```

- 主循环 `LOOP_DELAY = 0.02s`（50Hz）
- 按键一律**边沿触发**（`cur_X and not last_X`）
- **D-pad 冲突保护**：同时按 ←+→ 或 ↑+↓ 连续 3 帧 → 判定为误触并屏蔽
- 本文件**保留了大量 `print(">>> …")`** —— 连 USB 调试时能看到日志（小车一把 print 屏蔽了，本车没有，两车取舍不同）

### 5.2 遥控信号链（与小车一共用同一套算法）

```
死区过滤(±3) → 两段响应曲线(拐点20 → 输出18%，高段指数1.7) → ×SPEED_SCALE(0.65)
→ INVERT_VX/VY/OMEGA 方向校准 → face_flipped 翻转 → mecanum_kinematics() → 四轮 set_power()
```

- 左摇杆全向（含横移、斜行），右摇杆原地自旋
- 曲线低段线性保证**轻推即有 ≥18% 稳态输出**（高于电机堵转阈值 ~15%），杜绝"起步猛冲又停"

### 5.3 自动程序：两种"剧本格式"

按 `+` 进入，先 `_reset_drive_encoder_reference()` 把四轮编码器清零，再逐条执行。

**格式 A：连续轨迹步（老格式）**

```python
(持续秒, Vx, Vy, omega)
```

- 每步之间 `AUTO_RAMP_MS=40ms` 线性插值（防速度跳变打滑）
- 可选 `AUTO_ACCEL_MS` 步内梯形加速（当前 0 = 关）

**格式 B：指令步（新格式，字符串标签开头）**

| 标签                   | 含义                                                              |
| ---------------------- | ----------------------------------------------------------------- |
| `enc_move`             | 编码器闭环直/斜行（按功率比例把目标角度分给 4 轮，`move()` 到点） |
| `enc_rot`              | 编码器闭环原地自旋                                                |
| `enc_moverot`          | **边走边转**：平移+旋转目标叠加，一次性 `move()` 到位             |
| `open_move`            | 开环走 + 用四轮编码和实时纠偏航向（`OPEN_HEADING_*`）             |
| `motor`                | 任意编码电机 M1~M5 开指定功率                                     |
| `dc_motor`             | 任意直流 DC1~DC3 开指定功率（记入 `_dc_hold` 保持）               |
| `servo`                | 舵机 `move_to(角度, 速度)`，等待 `wait_ms`                        |
| `delay`                | 纯延时                                                            |
| `spin`                 | 时间驱动自旋（非编码器，转得快）                                  |
| `enc_stop`             | 停所有电机 + 清 DC 功率（`_stop_dc_all()`）                       |
| `traj_v` / `traj_stop` | GUI 连续轨迹专用步                                                |

- 编码器标定换算：`ENCODER_TICKS_PER_CM=70.287`、`TURN_TICKS_PER_DEG=11.1435`
- `_resolve_zero_enc_move()`：如果某步速度向量是 0（画轨迹留下的），自动用相邻步向量"补脑"
- 特殊能力：**连续 enc_move 步之间不刹停**（`stop_motors=False`），走位更顺

### 5.4 调试模式（≡）—— 四个硬件类别逐个测

| 类别     | 对象                   | 测试键                                                                             |
| -------- | ---------------------- | ---------------------------------------------------------------------------------- |
| 编码电机 | M1 / M2 / M3 / M4 / M5 | N1 正转 / N4 反转 / N2·N3 调速度(±10)                                              |
| 直流电机 | DC1 / DC2              | 同上                                                                               |
| 无刷电机 | BL1 / BL2              | N1 转 / N4 停                                                                      |
| 舵机     | SV1 / SV2              | N1 转到当前角度 / N4 回 0 / N2·N3 调角度(±2) / R1 设零点 / R2 存动作角 / L1 翻方向 |

- 切换：↑/↓ 换类别，←/→ 换对象，LED 显示对象名
- 可用来**现场标定**舵机动作角（R2 会把当前角度写回 `SERVO1/2_ACTION_ANGLE` 内存值）
- 调试里也能直接按 `+` 启动自动程序

## 7. 软件搭配上的注意点

1. **两车共用同一套遥控算法**（两段式响应曲线 + 死区 + 方向校准），
   但参数不同：本车 `SPEED_SCALE=0.65`、拐点 20、三向都做了反转校准；小车一 0.85、拐点 25。
2. **本车没有 try/except 全禁的约束那么敏感的历史包袱**，但同样建议少新增异常处理；
   关键差异是它**保留了 print 日志**（USB 调试友好），小车一则因内存/字节码把 print 换成空函数。
3. **舵机是"动作型"不是"保持型"**：摆到角度后 0.18s 自动回中 —— 改角度前想清楚它是往复动作。
4. **无刷互斥**：BL1/BL2 同一时刻只允许一个在转（防电流过大/结构干涉）。
5. **自动程序结束会清 DC 功率**（`enc_stop` → `_stop_dc_all`），但 `stop_all_motors()` 不清 DC ——
   这是刻意设计：手动按 N2/N4 开着的收球状态在自动结束后不会自己乱关/乱开。
