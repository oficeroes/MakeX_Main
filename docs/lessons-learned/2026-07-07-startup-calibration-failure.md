# 失败案例：开机自动校准（2026-07-07）

> **状态**：❌ 已回退  
> **影响**：机器人完全无响应（LED 不亮、电机不动）  
> **根因**：未能在真实硬件上验证，过度依赖代码逻辑推理

## 1. 功能设计

为 M4/M5 两个升降臂实现类似"拓竹 3D 打印机碰壁归零"的开机校准：

- 抬升 200° → 慢速下降至堵转（碰壁）→ 抬升 100° → 二次碰壁确认 → 双舵机全开

## 3. 失败过程（三轮修复，全部无效）

| 轮次 | 改动                                                  | 为什么还是不行                                                 |
| :--: | ----------------------------------------------------- | -------------------------------------------------------------- |
|  ①   | 初始实现                                              | 未保护异常，`novapi.timer()` 在 `reset_timer()` 前调用         |
|  ②   | 加 try-except + None 检查                             | 即使函数不崩溃，校准耗时过长（最多 64 秒），机器人表现像"死机" |
|  ③   | 外层 `except BaseException` + 缩短超时 + 电机就绪检查 | **仍然无法启动**——说明问题在更底层                             |

## 4. 根因分析

### 4.1 最可能的原因

**Novapi 平台的 MicroPython 对阻塞式 `while` 循环 + `time.sleep()` 组合在模块加载阶段极为敏感。**

校准函数在主循环启动**之前**执行。这意味着：

- 如果 `_calib_move_deg()` 内部的 `while` 循环因为任何原因（编码器读数异常、电机不转）跑满 `CALIB_TIMEOUT` 秒，机器人在这段时间内完全无响应
- 即使加了 `except BaseException` 兜底，校准期间触发的看门狗复位或内存问题仍可能导致系统重启
- Novapi 平台可能对开机后立即执行长时间阻塞操作有硬性限制（如看门狗定时器）

### 4.2 次要原因

1. **无法调试**：`print = _safe_print` 屏蔽了所有输出，完全不知道哪里出错
2. **无远程日志**：机器人没有串口/USB 终端，LED 是唯一界面，但 LED 更新可能在阻塞循环中来不及时刷新
3. **缺乏硬件验证**：所有修改都在没有真实硬件的环境下完成，无法逐行测试

### 4.3 为什么之前的功能（如 `apply_slew_rate`）没问题？

| 特性                | 执行时机               | 是否阻塞                                   |
| ------------------- | ---------------------- | ------------------------------------------ |
| `apply_slew_rate`   | 主循环内（每帧 0.02s） | ❌ 非阻塞，只做简单数学                    |
| `startup_calibrate` | 主循环**之前**         | ✅ 阻塞，`while` + `time.sleep` 可长达数秒 |

## 5. 教训

| #   | 教训                                                                                           |
| --- | ---------------------------------------------------------------------------------------------- |
| 1   | **不能在 `while True` 之前做任何阻塞操作**。所有耗时逻辑必须放在主循环内用状态机实现           |
| 2   | **必须先确保脚本能启动，再逐步加功能**。每次只改一个函数、验证后再改下一个                     |
| 3   | **在没有终端输出的平台上，LED 是唯一的"printf"**。调试时应保留 `print` 或使用 LED 显示变量值   |
| 4   | **编码器读数在上电瞬间可能不稳定**。`get_value("angle")` 可能返回 `None`、0、或随机值          |
| 5   | **`novapi.reset_timer()` 必须在任何 `novapi.timer()` 调用之前执行**——文档明确写了这个用法      |
| 6   | **保守的异常处理（`except BaseException`）不能解决根本问题**——它只能防止崩溃，不能修复逻辑错误 |

## 6. 如果要重新实现

建议方案：**状态机模式**，在主循环内实现。

```python
# 校准状态机（在主循环内，不阻塞）
_calib_state = 0        # 0=空闲, 1=M4抬升, 2=M4下降, ...
_calib_phase_start = 0.0

def calib_tick():
    """每帧调用，非阻塞状态机"""
    global _calib_state
    if _calib_state == 0:
        return  # 空闲
    # ... 状态切换逻辑 ...
```

关键原则：

1. 每帧只做一个微小操作（设置功率、读取编码器、检查超时）
2. 用 `novapi.timer()` 而不是 `time.sleep()` 控制时序
3. 校准期间遥控照常响应（或至少能紧急停止）
4. LED 在主循环内正常刷新
